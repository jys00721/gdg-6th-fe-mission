# Refactoring Custom Hooks 정리

## Refactoring이란?

**Refactoring**은 코드의 기능은 그대로 유지하면서, 코드의 구조를 더 보기 좋고 관리하기 쉽게 바꾸는 작업이다.

즉, 결과 화면이나 동작은 바뀌지 않지만 코드 내부 구조를 개선하는 것이다.

예를 들어 다음과 같은 작업들이 리팩토링에 해당한다.

- 너무 긴 컴포넌트를 여러 컴포넌트로 나누기
- 반복되는 코드를 함수로 분리하기
- 변수명을 더 이해하기 쉽게 바꾸기
- 페이지 역할과 컴포넌트 역할을 분리하기
- API 요청 로직을 별도 파일로 분리하기
- 자주 사용하는 Hook 로직을 Custom Hook으로 만들기

---

## Refactoring을 하는 이유

리팩토링을 하면 코드의 유지보수성이 좋아진다.

예를 들어 하나의 컴포넌트 안에 검색, 목록 출력, 버튼 처리, API 요청, 상태 관리 코드가 모두 들어있으면 처음에는 편해 보일 수 있다.

하지만 나중에 코드를 수정하려고 하면 어디를 고쳐야 하는지 찾기 어려워진다.

반대로 역할별로 코드를 나누면 다음과 같은 장점이 있다.

- 코드의 역할이 명확해진다.
- 수정해야 할 위치를 찾기 쉬워진다.
- 같은 코드를 여러 번 작성하지 않아도 된다.
- 컴포넌트를 재사용하기 쉬워진다.
- 협업할 때 다른 사람이 코드를 이해하기 쉬워진다.

---

## 관심사의 분리란?

**관심사의 분리**는 하나의 코드가 너무 많은 역할을 하지 않도록 역할별로 나누는 것을 말한다.

여기서 관심사란 “코드가 담당하는 역할”이라고 이해하면 된다.

예를 들어 쇼핑몰 프로젝트에서 다음과 같이 역할을 나눌 수 있다.

```txt
pages 폴더
- 페이지 전체 화면을 담당
- 라우팅 단위의 화면을 구성

components 폴더
- 버튼, 헤더, 상품 카드처럼 재사용 가능한 UI를 담당

apis 폴더
- 서버와 통신하는 API 요청 로직을 담당

hooks 폴더
- 여러 컴포넌트에서 반복되는 React Hook 로직을 담당
